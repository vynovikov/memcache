# memcache
memcache — это минималистичный, высокопроизводительный in-memory кэш с низким уровнем задержек (low-latency). Разработан как легковесная библиотека, которая встраивается напрямую в код вашего Go-приложения, и поддерживает шардирование, LRU-вытеснение и TTL-истечение записей.

Кэш решает три ключевые задачи:
* снижение нагрузки на CPU, вызванной конкуренцией за блокировку ([**lock contention**](#lock_contention))
* вытеснение элементов, к которым дольше всего не было обращений ([**Least recently used**](#lru))
* контроль времени жизни каждой записи, по истечении которого она удаляется из памяти ([**Time-to-live**](#ttl))

<a id="lock_contention"></a>

### Lock contention

При одновременном доступе на запись к кэшу нескольких горутин для защиты внутренних структур и предотвращения гонок данных (data race) требуется синхронизация с помощью мьютекса. При этом если мьютекс один на весь кэш, а обращений много, то большая часть времени уходит просто на ожидание в состоянии блокировки. Эта проблема решена с помощью шардирования. Кэш разделен на независимые сегменты (шарды) с индивидуальным мьютексом.

#### Вычисление индекса шарда

Определение шарда для пары "ключ-значение" всегда однозначно и выполняется с минимальными затратами процессора благодаря двум архитектурным решениям:

**Количество шардов** - степень двойки. Благодаря этому для вычисления индекса шарда мы можем использовать побитовую арифметику, идеальную для CPU

**Хэш-функция** - мгновенно вычисляет числовое значение на основе ключа, соблюдая два правила:
- хэш от одного и того же ключа всегда одинаков
- хэши от двух похожих ключей кардинально отличаются друг от друга

Определение нужного шарда сводится всего к одной операции: побитовому И (AND) между хэшем ключа и числом, равным количество шардов минус 1

```
111001100001101010011011010100101 (хэш)
AND
000000000000000000000000000011111 (количество шардов минус 1)
=
00101 (то есть 9 в десятичном представлении)
```
получим последние биты хэша. Их десятичное представление и является индексом шарда.


<a id="lru"></a>

### LRU

Вытеснение элемента, к которому не обращались дольше всего реализовано на базе двусвязного списка (doubly linked list). Это линейная цепочка узлов. Каждый узел хранит ключ и два указателя: на предыдущий и последующий узлы. У самого первого узла списка **HEAD** указатель на предыдущий элемент равен nil. Соответственно,  у самого последнего узла **TAIL**  указатель на последующий элемент так же равен nil

- при обращении к нужному элементу мы просто меняем указатели соответствующего узла и его соседей, перемещая его в начало списка
- при превышении максимального числа узлов мы замыкаем указатели соседей самого последнего элемента друг на друга

Эти операции выполняются за константное время и гарантируют что кандидат на вытестение каждый раз оказывается в хвосте списка

### TTL

Очистку записей с истекшим сроком жизни нам помогает реализовать другая структура данных -  бинарная куча (**Min-heap**). Это линеаризироанное представление бинарного дерева, сбалансированного по ветвям

Min-heap

<img src="assets/heap.jpg" alt="Heap">

Куча получается упорядочиваниеем узлов дерева в слайс по принципу

```
индекс левого потомка = 2 * инденкс родителя + 1
индекс правого потомка = 2 * инденкс родителя + 2
```

Основное свойство такого дерева дерева - родитель всегда меньше любого из своих потомков. Это означает, что каждая ветвь (узлы от самого младшего потомка до самого старшего родителя) отсортирована по неубыванию сверху вниз. При этом потомки одного родителя могут и не быть отсортированы между собой.

Все это обеспечивает нахождение узлов с истекшим временем жизни в начале кучи. Нам остается только удалить элементы из начала кучи и перебалансировать ее. Поскольку этот процесс совершается фоновым воркером, он не влияет на производительность кэша.

Для сортировки каждой ветви применяется алгоритм **shift-up**: новый элемент добавляется в конец кучи, затем последовательно сравнивается с родителями и меняется с ними местами, если он меньше родителя. Как только найден родитель меньше нашего элемента, сортировка прекращается. Такой алгоритм обеспечивает необходимую балансировку кучи за логарифмическую сложность по времени.
